## Bug 原因分析

### 现象
从游玩记录可见：
1. 第3回合：玩家"大成功"偷走《破旧的书》和《泛黄纸条》
2. 系统提示物品 location 已变为 `char-player-01`（在玩家背包中）
3. 但第4、5回合执行 `\inventory` 都显示"**背包是空的**"

### 根本原因：**内存状态与 IO 层状态不一致**

**数据流向：**
1. LLM 生成 StateChange 更新物品 location（如 `item-book-01.location = "char-player-01"`）
2. [`game_engine._apply_changes()`](src/engine/game_engine.py:915) 调用 `io.apply_state_change()` 保存到 IO 层
3. IO 层的 [`_save_item_with_relationship_sync()`](src/data/io_system.py:534) 会**级联更新**：
   - 保存物品的 location
   - **同时更新角色的 inventory**（将物品加入 `char-player-01.inventory`）
4. 然后 `_sync_state_change()` 同步内存状态——**但只同步被变更的实体（物品），没有同步被级联更新的角色 inventory**

**问题代码位置：** [`game_engine.py:1158-1174`](src/engine/game_engine.py:1158)
```python
def _sync_state_change(self, change: StateChange):
    # 只同步变更指定的实体，忽略了 IO 层的级联更新
    if change.id in self.game_state.characters:
        char = self.game_state.characters[change.id]
        self._update_entity_field(char, change.field, change.value, change.operation)
    elif change.id in self.game_state.items:
        item = self.game_state.items[change.id]
        self._update_entity_field(item, change.field, change.value, change.operation)
```

**结果：**
- IO 层（数据库/JSON）：`char-player-01.inventory = ["item-book-01", "item-note-01"]` ✓
- 内存中：`player.inventory = []` ✗
- 执行 `\inventory` 时从内存读取，显示为空

### 解决方案建议
需要在 `_apply_changes()` 中，IO 层保存成功后，**重新从 IO 层加载被级联影响的相关实体**到内存，确保内存状态与持久化层一致。或者修改 `_sync_state_change` 来处理 inventory/location 的双向同步逻辑。

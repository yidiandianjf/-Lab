# AEngine 现字段到目标协议映射表

**日期:** 2026-03-28  
**用途:** 将当前主链路中的真实字段映射到“信息链路九要素模型”，并给出保留 / 合并 / 拆分 / 删除 / 下沉代码 的处理策略。  
**理论依据:** `docs/review/信息链路要素体系与理论框架.md`

---

## 1. 使用说明

本表不是简单字段清单，而是用于指导重构决策。

每个字段都回答 7 个问题：

1. **当前字段是什么**
2. **它属于九要素中的哪一类**
3. **当前由谁生产**
4. **当前由谁消费**
5. **为什么现在不稳定**
6. **未来应该变成什么**
7. **迁移时应如何处理**

---

## 2. 处理动作定义

| 动作 | 含义 |
|------|------|
| `保留` | 当前字段职责清晰，继续存在 |
| `重命名` | 字段本质合理，但名字不准确 |
| `合并` | 与其他字段表达同一事实，应合并为更高层对象 |
| `拆分` | 当前字段承担多重职责，应拆成多个字段 |
| `下沉代码` | 不应继续由 LLM 负责，改由代码维护 |
| `适配保留` | 迁移期短暂保留，仅通过适配器桥接 |
| `删除` | 无清晰职责、已被覆盖或属于历史遗留 |

| 编号 | 要素 | 说明 |
|------|------|------|

## 5. 关键归并结论

## 5.1 必须合并的

1. `player_check_result` + `player_resolution_anchor`  
   目标：统一为 `TurnResolution`

2. 分散的 `check_*` 字段  
   目标：统一为 `CheckPlan`

3. 玩家/NPC 的步骤级输出  
   目标：统一为 `TurnStep`

---

## 5.2 必须拆分的

1. `action_description`  
   拆为：
   - `raw_input_text`
   - `intent_text`

2. `additional_context` / `engine_context` / `game_context`
   拆为：
   - `WorldStateView`
   - `DialogueMemoryView`
   - `NarrativeMemoryView`
   - `TurnTraceView`

3. `narrative_context`
   拆清职责：
   - `NarrativeMemory`
   - `TurnTrace`

---

## 5.3 必须下沉代码的

1. `actionable_npcs`
2. `npc_actor_id` 合法性
3. `check_target` 合法性
4. `difficulty` 枚举合法性
5. `check_attributes` 规则合法性
6. 状态变更字段路径合法性

---

## 5.4 应删除或逐步淘汰的

1. `engine_context`
2. Prompt 中遗留的旧字段说明
3. 仅为兼容旧流程存在的模式拼贴字段
4. 不能回扣到九要素中的杂项上下文字段

---

## 6. 迁移顺序建议

### 第一批：先定协议

1. `raw_input_text`
2. `intent_text`
3. `CheckPlan`
4. `TurnResolution`
5. `TurnStep`
6. `TurnTrace`

### 第二批：再拆上下文

7. `WorldStateView`
8. `DialogueMemoryView`
9. `NarrativeMemoryView`
10. `NpcWorldView`

### 第三批：最后清理旧字段

11. `action_description`
12. `player_resolution_anchor`
13. `player_check_result`
14. `engine_context`
15. `player_intent` 整包传递

---

## 7. 一句话结论

当前字段体系最大的问题，不是字段多，而是**字段没有被组织进一条有本体边界、时间边界、权威边界的信息链**；这张映射表的作用，就是把每个字段重新放回它应在的位置上。
